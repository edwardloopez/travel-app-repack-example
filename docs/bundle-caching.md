# Bundle Caching Implementation

## Overview

This implementation adds Module Federation bundle caching to the travel app using Re.Pack's ScriptManager, preventing the need to re-download remote bundles once they've been cached locally.

## Architecture

### BundleCacheProvider Component

Located in `packages/travel-core/src/components/BundleCacheProvider.tsx`

**Key Features:**
- Uses `ScriptManager.shared.setStorage()` from `@callstack/repack/client`
- Implements AsyncStorage for persistent bundle caching
- Wraps the entire application to enable global bundle caching
- Provides automatic cache management with proper Re.Pack integration

### Implementation Details

```typescript
// Correct usage following Re.Pack documentation
import { ScriptManager } from "@callstack/repack/client";
import AsyncStorage from '@react-native-async-storage/async-storage';

// Configure ScriptManager with AsyncStorage for bundle caching
ScriptManager.shared.setStorage({
  getItem: (key: string) => AsyncStorage.getItem(key),
  setItem: (key: string, value: string) => AsyncStorage.setItem(key, value),
});
```

### Integration

1. **Travel-Core Package:**
   - Added `@react-native-async-storage/async-storage` dependency
   - Added `@callstack/repack` dependency
   - Exported `BundleCacheProvider` component

2. **Travel-Host App:**
   - Wrapped main App component with `BundleCacheProvider`
   - Bundle caching now applies to all Module Federation loads

## Benefits

1. **Performance:** Cached bundles load instantly after first download
2. **Offline Support:** Previously loaded micro-frontends work offline
3. **Bandwidth Savings:** Reduces network usage for repeated bundle loads
4. **User Experience:** Faster navigation between micro-frontends

## How It Works

1. When a remote micro-frontend is first loaded:
   - Bundle is downloaded from the remote server
   - Bundle metadata is stored in AsyncStorage cache
   - Bundle is executed normally

2. On subsequent loads:
   - ScriptManager checks AsyncStorage cache first
   - If cache hit, bundle loads from local storage (instant)
   - If cache miss, falls back to network download

## Cache Management

- **Storage Backend:** AsyncStorage (persistent across app restarts)
- **Cache Key:** Generated by ScriptManager based on bundle URL and version
- **Automatic Cleanup:** ScriptManager handles cache invalidation
- **Manual Clearing:** Can be cleared by removing app data or using ScriptManager.shared.invalidateScripts()

## Usage

Bundle caching is automatically enabled for all Module Federation components:

```typescript
// This will automatically use caching
const RemoteComponent = React.lazy(() => import('RemoteMicroFrontend/Component'));
```

## Testing

1. Start travel-host app with caching enabled
2. Navigate to any micro-frontend (first load = network download)
3. Navigate away and back (second load = cache hit, instant load)
4. Check console logs for cache behavior in development mode
